# 스쿼드 메이커 구현 계획

> **에이전트에게**: 이 계획은 단계별로 나눠 실행한다. 각 단계가 끝날 때마다 `npm test`,
> `npx tsc --noEmit`, `npm run lint`, `npm run build` 가 통과해야 한다.

**목표:** 혼자서 모드에서 모아둔 선수를 포메이션에 배치하고, 그 스쿼드의 가치를 보고,
결과 화면에 자랑거리로 남긴다.

**성격:** 전시·트로피 층이다. **경제에 닿지 않는다.** 스쿼드 가치는 점수로만 보여주고
팩값·강화비·파산 판정에 아무 영향을 안 준다. 강화 곡선을 여러 번 갈아엎어 맞춰둔 세 구간
규칙(`economy.ts`)이 흔들리면 안 된다.

---

## 왜 만드나

지금 혼자서 모드는 뽑고·강화하고·파는 게 전부다. 모은 카드가 보관함에 쌓이기만 하고
"내 팀"이 되지 않는다. 참고한 웹 축구게임들(38-0, Copero)이 공통으로 가진 게 **결과를
한 장으로 보여주는 화면**인데, 카드 세 장 나열보다 포메이션에 꽂힌 스쿼드가 훨씬 강하다.

## 결정된 것

- 포메이션은 다섯: `4-3-3` `4-4-2` `4-2-3-1` `3-4-3` `3-5-2`
- 포지션 제한은 **대분류만**: 골키퍼 / 수비 / 미드필더 / 공격수
- FotMob 서브 포지션은 **안 쓴다.** `epl.ts` 가 `Positions` 배열의 첫 번째만 저장하고
  버려서 데이터에 없다. 대분류만으로도 충분히 느슨하다
- 스쿼드에 같은 선수를 두 자리에 못 넣는다
- 저장은 `Run` 안에 넣고 스키마 버전을 올린다. 굴리던 판은 초기화된다
- 스쿼드에 넣은 카드를 팔거나 강화하다 터뜨리면 스쿼드에서 자동으로 빠진다

## 파일 구조

| 파일 | 맡는 일 |
|---|---|
| `app/_solo/squad.ts` | 규칙(순수 함수). 슬롯 정의·배치 가능 판정·가치 계산 |
| `squad.test.ts` | 위 규칙 테스트 |
| `app/_solo/squad-field.tsx` | 필드 그림과 슬롯 배치 |
| `app/_solo/squad-picker.tsx` | 슬롯을 눌렀을 때 뜨는 선수 고르기 팝오버 |
| `app/_solo/squad-panel.tsx` | 스쿼드 판 전체(포메이션 고르기 + 필드 + 가치) |
| `app/_solo/storage.ts` | `Run.squad` 추가, VERSION 올림 |
| `app/_solo/solo.tsx` | 스쿼드 상태 지휘, 판매·강화 시 정리 |
| `app/_solo/result.tsx` | 스쿼드를 메인으로 |

`solo.tsx` 는 이미 325줄이다. 스쿼드 로직을 여기 쌓지 말고 위 파일들로 뺀다.

## 단계

### P1. 규칙층 (`squad.ts` + `squad.test.ts`)

종목이 서로 다르므로 슬롯 정의를 종목별로 가른다.

**축구**: 포메이션마다 슬롯 11개. 각 슬롯은 `{ id, group, label, x, y }` 다.
`group` 은 `GK | DF | MF | FW`, `x`·`y` 는 필드 위 백분율 좌표다.

**야구**: 포메이션이 없다. 슬롯이 고정이다.

- 타자 9: 포수 1, 내야수 4, 외야수 3, 지명타자 1
- 투수 10: 선발 5, 중계 4, 마무리 1

배치 좌표는 위에서부터 외야수 → 내야수 → 포수, 그 아래에 투수진이다.

**배치 가능 판정**: 카드의 역할을 슬롯 그룹에 대응시킨다.

- 축구(`role` 기준): 골키퍼→GK · 센터백·풀백→DF · 미드필더·공격형MF→MF · 윙어·스트라이커→FW
- 야구: 타자는 `pos`(포수/내야수/외야수)로, 지명타자 슬롯은 타자 아무나.
  투수는 `role`(선발/불펜)로, 마무리 슬롯은 불펜 아무나

**스쿼드 가치**: 꽂힌 카드의 `cardValue` 합. 다만 **주 포지션이 슬롯과 정확히 맞으면
1.2 배**를 준다. 대분류만 맞고 세부가 다르면(풀백을 센터백 자리에) 배수가 없다.
1.2 는 첫 값이라 붙여보고 조인다. 근거를 주석에 남긴다.

빈 슬롯은 0 으로 친다.

### P2. 저장 (`storage.ts` + `solo.tsx`)

`Run` 에 `squad` 를 넣는다. 모양은 `Record<슬롯id, Owned>` 로, 빈 슬롯은 키가 없다.
축구는 포메이션도 같이 저장한다.

`parseRun` 이 모양과 범위를 검사한다. 지금 `vault`·`best` 를 검사하는 방식과 같게 한다.
**스키마가 바뀌므로 `VERSION` 을 3 으로 올린다.**

`sell()` 과 `upgrade()` 에서 카드가 보관함에서 빠지면 스쿼드에서도 뺀다. 예전에 풀에
없는 카드 하나가 파산 판정을 영영 막았던 것과 같은 종류의 사고다. 정산은 지금처럼
`setRun` 업데이터 안에서 커밋된 상태로 한다.

### P3. 스쿼드 판 (`squad-field.tsx` · `squad-picker.tsx` · `squad-panel.tsx`)

슬롯을 누르면 팝오버가 뜬다. **그 슬롯에 들어갈 수 있는 카드만** 보여준다.
슬롯에 이미 선수가 있으면 교체·제거도 할 수 있다.

반대 방향도 연다. 카드 상세(`enlarged-card.tsx`)에 "스쿼드에 넣기"를 더하고,
누르면 작은 필드가 팝오버로 떠서 **그 카드가 들어갈 수 있는 슬롯만** 밝게 보여준다.

**드래그드롭은 이 단계에서 안 만든다.** 모바일에서 까다로워서 팝오버가 없으면 폰에서
아무것도 못 한다. 팝오버가 먼저고 드래그는 마지막 단계다.

### P4. 레이아웃 (`solo.tsx`)

- PC: 좌측에 상점·보관함, 우측에 스쿼드 판
- 모바일: 왼쪽 모서리에 책갈피 탭만 접혀 있고, 누르면 스쿼드가 펼쳐진다

### P5. 결과 화면 (`result.tsx`)

스쿼드를 메인으로 올린다. PC 는 좌우(스쿼드 · 가치순/강화순 top3), 모바일은 상하.

### P6. 드래그드롭

마지막. 팝오버로 이미 다 되는 상태에서 얹는 것이다.

---

## 검증

각 단계마다 브라우저로 직접 본다. 개발 서버는 3100 포트다.

- 야구와 축구가 서로 다른 필드를 그린다
- 못 들어가는 슬롯이 잠기거나 팝오버 목록에서 빠진다
- 같은 선수를 두 자리에 못 넣는다
- 스쿼드에 넣은 카드를 팔면 스쿼드에서 빠진다
- 390px 에서 책갈피 탭과 펼친 화면이 안 깨진다
- 스쿼드 가치가 손계산과 맞는다
